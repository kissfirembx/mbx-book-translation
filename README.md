# mbx-book-translation

把整本书或长篇文章翻译成中文，也能只转 Markdown。

## 为什么用它

Agent 自己会翻译。短文章、单段文字，直接让它翻就行，不需要这个 skill。

但整本书像一个翻译项目，不是一次问答：

- 几百页，一口气翻，容易忘前面的人名，漏页、并段；
- 同一个人名、同一本书的术语，前后要一个说法；
- 扫描件要先认字，不能直接当文本读；
- 翻完还要查：有没有漏译、数字和单位对不对、段落有没有少。

这个 skill 就是把这些事固定成流程，并配上检查工具。它不靠 Agent 当场记，靠的是文件、脚本和规格。

## 它像一个什么样的翻译团队

像一个有译名表、作者风格卡、术语库和审校清单的翻译团队：

- **译名表**：人名、地名、书名、专有名词固定下来，后面每章都用同一套。
- **作者风格卡**：同一个作者的语气、称呼、标点、强调方式，可以沿用。
- **术语库 / 习语库**：同一系列、同一题材的词和固定说法，越翻越厚。
- **审校清单**：段落、数字、单位、页码、标记、漏译，用脚本查，不靠「感觉差不多」。

所以翻同一个作者、同一个系列，下一本会更顺，不是每次从零开始。翻得越多，库越厚，下一本越准。

## 它具体做什么

1. **拆书**：PDF / EPUB / DOCX 按章切开；扫描书先 OCR。
2. **体检**：查页数、字数、缺页、图片、乱码。
3. **统一说法**：人名、地名、术语先定好，写进术语库和作者档案。
4. **按窗口分派任务**：根据你用的模型能装多少上下文，算每个子 Agent 做几章；不是固定一章一个，也不是全书硬塞。
5. **逐章翻译**：一章章来，长书可以分多次跑；同一个 Agent 接着翻，前面读过的内容不用再读一遍。
6. **机器检查**：段落、数字、单位、页码、标记、漏译。
7. **合成**：按书名和章节输出 Markdown；也可以只转 MD。

## 上下文怎么安排

不同模型窗口不一样。这个 skill 会算三笔账：

- 源文占多少 token；
- 译文预计占多少 token；
- 每个 Agent 的固定开销多少。

然后用 `plan_batches.py` 按「你设定的用量」分派任务。默认用量 50%——上下文用到一半后，模型可能开始变笨，不是塞满 100%。一个章节很小，只占窗口一点，所以会把多章分给一个 Agent，直到接近这个用量；如果你另设了单 Agent 产出上限，也到上限为止。目标是：不把上下文塞满、不浪费窗口、不让一个 Agent 干到后面质量掉下来。

## 和直接让 Agent 翻的区别

- **有记忆**：作者档案、术语库、习语库会留下来；同一个作者、同一个系列，下一本接着用。
- **有工序**：拆书、体检、统一说法、逐章翻译、机器检查、合成；不是一段提示词。
- **会算账**：按模型窗口分派任务，省上下文、少重复读、少返工。

## 适合 / 不适合

适合：整本书、长篇文章、连载、作者自媒体长文、扫描书。

不适合：一句话、短截图、单页短文。

## 安装

```bash
npx skills add kissfirembx/mbx-book-translation
```

需要 Python 3.10+，并安装依赖：

```bash
pip install -r requirements.txt
```

扫描书另需 PaddleOCR-json，外部程序，不随仓库分发。

## 使用

直接对 Agent 说：

> 把这本书翻译成中文。

> 把这篇长文翻译成中文。

> 这本扫描书先 OCR，再翻译。

> 这本只转 Markdown，不翻译。

不用套固定句式。输出目录、是否翻译、质量档，Agent 会按流程确认；如果你有自己的目录习惯，直接告诉它。

配置项见 `references/环境与配置.md`。
