# 模式 A：文本层 PDF/EPUB 翻译（详细步骤）

> 主入口只保留流程与停止条件；本文件是 A1-A5 的完整步骤与约束。2026-10-07 自 `SKILL.md` 搬出（主入口减重）。

### A1. 提取与切分

> 先跑通用提取器：PDF 用 `scripts/extract_pdf_text.py`（按书签切章），EPUB 用 `scripts/extract_epub_text.py`（按 spine + TOC）。只有书签/TOC 缺失或版式特殊时才手工 PyMuPDF，并在《翻译任务规格.md》记原因。
>
> 长文/连载：按 Markdown 标题或自然小节切 `source_en/`；没有书级目录就跳过目录页解析；输出根用 `<标题>/`；术语库可选，其余仍走 A2–A5。

1. PyMuPDF 提取全部文本；用「每页首行 + 页字符数」扫描定位章节边界
2. 从目录页（TOC）解析章节清单：`第X章标题/印刷页码`；注意「章节标题跨行」「页码无斜杠分隔」（如 `3.xxx144`）——正则要兼容
3. 按章节切分为独立 txt（`source_en/`），每页加 `[PDF 第 X 页]` 标记（翻译时忽略、核对时有用）
4. 检测纯图片页（文本 <50 字符且有图）→ 标记 `[图片页]`，提取整页渲染图，翻译时嵌入原图
5. **EPUB 图片提取**：图片可能嵌在 `<div>` 里而不在 `<p>` 里——必须扫描全部 `img` 标签（不限定父元素）并检查父元素，否则章节图会全部静默丢失（实战：82 张图全部未提取）
6. **EPUB 重复标题**：跳过与 TOC 标题重复的书眉标题；正文中的展平重复列表是提取产物，完整保留——**译者禁止自行删重复**，统一在 A3 用 `clean_flat_lists.py` 清理
7. **EPUB 图片一律按 `<img>` 前后文内嵌**（标注「原文插图」）；只有确实定不了位的才集中放置并登记原因。**引用路径必须带前缀**（裸文件名在 Obsidian 中会断图，历史上 4 本书共 415 处断链）：书根 `./figs/`、`zh/` 子目录 `../figs/`，`merge_book.py` 合并时改写为 `./figs/`
8. **EPUB 源无图片页标记**时，图片位置回原 EPUB 核对（解包后在 `OEBPS/` 下用 `toc.ncx` 或正文唯一字符串定位本章 `.xhtml`）；先在体检阶段生成书级 `chapter-figs.json`（章 → 有序图片名），翻译时把对应行交给译者，译者只判断「图落在哪一行」。**必须从 EPUB 生成，不要从旧译稿反推**
9. **提取后必跑覆盖率核查（硬卡口）**：`scripts/check_epub_coverage.py --epub <书.epub> --source-dir <书>/source_en --fig-map <书>/chapter-figs.json --ignore <前置页 xhtml 列表>`，退出码非 0 就停下来补提取。起因：EPUB 常把一章拆成多个 spine 文档，**续页没有自己的章标题**，按标题切分的脚本会整段丢掉。案例与判定口径见 `references/已知坑.md`

### A2. 翻译执行（并行 agent）

- **OCR 源先做质量体检**：`source_en` 若来自「丢空格」的转换管道会出现大量粘连（实测某书 1,513 处小写接大写），**翻译前先跑 `scripts/rebuild_source_from_ocr.py`**（默认 dry-run，再 `--apply`）
- **重复页眉/页脚丢弃**：扫描件每页页眉多与章标题重复，删掉即可，**不要升格为标题**
- **先读术语体系**（**由主流程读，不交给译者**）
- **建《翻译规范与术语表.md》**（**过程产物**）：书级术语表（小书 20-40 条，长书 40+ 条）+ 专名表（按 `references/译名规范.md` 查权威来源）+ 格式规范（`#` 章 / `##` 节 / `###` 子节、表格重建、引号用「」、中英文间空格）+ 术语裁决记录——A5 沉淀后删除
- **术语表 + 小样一并确认**（依据 GB/T 19363.1-2003 第 4.4.2.2 条）：建表后抽 3–5 处成节（每处 8–12 段连续文本，跨章，覆盖叙事/对话/清单/数字/术语密集/幽默，优先含已知陷阱；总量 ≥3000 中文字），把「术语表 + 冲突裁决 + 小样风格」交使用者过目；**精确档确认后才进批量，自读档不强制等、按默认继续并标注**。
- **小样落点与命名**：`_过程/小样/第N回小样_YYYY-MM-DD/`（含 `_源文/`、`<序号>_<类型>_<章号>_<中文章名>.译.md`、`_本回说明.md`）；反馈 `第N回反馈_YYYY-MM-DD/`（`反馈.md`、`修订版/`）；开新回次不覆盖旧回次。小样确认通过后才并入 `zh/`。

> 术语表 + 小样未过 S4/G2 前，不启动批量翻译。理由：40+ 核心术语的统一是全书质量基线。

- **规范冻结门**：批次 1 之前把「术语 + 格式 + 本章图锚点 + 本类型语义不变量（`types/<类型>.md` 同名栏，并入书级 `{FORMAT_BLOCK}`）」冻成两份东西——① 书级《翻译规范与术语表.md》（人看）；② 每章的**内联简报**（机器看，直接拼进 prompt）。冻结前逐条自问「上次踩过的坑是否都已写入」。**批次开始后除硬错误外不再改规则**——实测返工全部来自规范后补
- **按合章启动翻译 agent**（默认一个 agent 一个批次，单 agent 产出 ≤2.5–3 万中文字；全书按体量拆成 1–4 个批次），**prompt 用固定模板、规范内联**：`references/executor-prompt-templates.md` 的「翻译执行者」模板——术语切片、**习语切片**、格式清单、插图锚点**直接内联**，**译者只读源文一个文件**；切片由 `scripts/build_slice.py` 自动生成（译者看不到术语库，「规则在库里没内联＝没写」）
  - ⚠️ **术语切片必须带「译名」**：只内联 `Offer→方案` 而漏了已定人名，译者会自行音译。**没内联的东西，译者一定会自己发挥**
  - ⚠️ **习语内联必须带语境条件**：无条件内联 `bottom line → 净利润`，译者会把 `## Bottom Line:`（**小标题义**）全译成「净利润：」——**比不内联更差**。表里没写条件的条目，宁可不内联（依据见 `references/关于流畅度质检.md`）
  - **译者禁止探索与自检**：不得解包 EPUB、渲染 PDF、grep 全书、读其他章或旧稿；写完即止
  - **输出契约一行**：路径 + 字数 + 完成标记 + 异常项
- 每个 agent 硬性要求：完整翻译不跳段、文末写 `<!-- 本章翻译完成 -->`、遇乱码写 `<!-- 未翻译：[原因] -->` 并继续
- 图片页要求嵌入原图（路径 `./figs/` 或 `../figs/` + `p<页码>_<序号>.png`）

### A3. 合并排版

- 合并脚本按文件顺序拼接（不生成手写目录块——MD 标题层级即大纲，Obsidian 大纲面板自动生成目录）
- 层级重映射：部分 > 章 > 节 > 子节（原书 Section > Chapter 结构；章文件整体 +1 级）
- **图片引用在成品内统一 `./figs/`**：`merge_book.py` 把章节里的 `](../figs/` 改写为 `](./figs/`
- **合并前先清展平重复**（EPUB 源）：`scripts/clean_flat_lists.py --dir <书>/zh --min-len 8`（默认 dry-run）。判定为「条目必须在前文全部逐字出现」才删：实测放宽到 70% 会误删真正的章尾清单。清理后逐章比对图片集合（应完全一致）
- 完成后核对：完成标记 N/N、未翻译标记 0、图片引用与文件 1:1、**全部图片引用带 `./figs/` 前缀且目标文件存在**（`merge_book.py` 不校验图片，合并后必须另跑一次校验）

### A4. 质量审校（依据 GB/T 19682-2005 第 4、5、7、8 章与附录 A）

> 🔴 **强度按档位分。别把精确翻译的流程套到自读上**：
>
> | 档 | A4 做哪些 | 产出形态 |
> |---|---|---|
> | **自读** | 只做下面标 **[自读]** 的项——全是**零 token 的确定性检查**（正则 / 查表 / 结构比对）+ 验收判定 | **不产出任何要使用者判断的候选清单**，一次跑完直接交付 |
> | **精确翻译** | 标 **[精确翻译]** 的项全部启用 | 产出《审校差错清单》，附抽检记录，交使用者复核 |
>
> **为什么自读也要跑机械项**：它们是确定性的——报 0 就是通过，报了就是真问题，**不需要使用者回来判断**。

**A4.0 机械校验前置（零 token，先跑脚本再审校）**——规则内联只覆盖已知陷阱，未知项靠脚本兜：

**[自读]** 1. `scripts/check_numbers.py --book-dir <书目录>`：折扣方向、数字对齐、`Nx more`→「高 N 倍」。报出的每条都带**原文片段**，人工 3 秒定性。
**[自读]** 2. `scripts/check_structure.py --book-dir <书目录> --outline`：结构件清点 + **源文小节清单 → 译文标题**逐条核对。**逐条核对大纲是整块漏译的最终防线**（整块漏译时计数往往只差一处、不触发阈值，是按大纲逐条点数才发现的）。
**[自读]** 3. **点缺陷四检**（命中即改、无需判断）：`check_idiom.py`（默认只报「错译」档；`--include-maybe` 的「待查」档噪声极大，默认关闭）、`check_unit_residue.py`、`check_markup.py`、`check_rare_chars.py`。
**[精确翻译]** 4. `check_fluency.py`（翻译腔指纹排序，输出 top 5% 段落）＋ `check_word_rarity.py`（生僻用词候选，只出候选不判定）。**两者都是召回优先的筛子**，报出的每条都要人工 3 秒定性（假阳性：专名、书名、公式段、作者刻意的措辞）。

> **点缺陷只能靠查表与正则**：`check_fluency` 量的是**段落密度**，对「整段都通顺、就一个词或一个字不对」的点缺陷完全无感（实测对人工判定的 5 处点缺陷 0/5 命中）。**各脚本的适用范围、实测精度与「评估后不采用」的结论见 `references/关于流畅度质检.md`。**

**差错定级与合格判定**：差错分四类（I/II/III/IV，系数 3 / 1 / 0.5 / 0.25，重复性错误按一次计算），合格判定按第 4.1 条与第 7.4 条，抽检范围按第 8 条。两条硬线：**I 类差错必须为 0**；**综合差错率 ≤0.3‰（内部收紧线）、不超 1.5‰（国标线）**。另设内部密度线：II 类 ≤3 处/万字符、III 类 ≤5 处/万字符。完整表格见 `references/翻译规范.md` 第六节。

- `综合差错率 = K × CA × (3·D_I + D_II + 0.5·D_III + 0.25·D_IV) ÷ W`；`W` = 译文字符数（全书验收用全书字符数，逐章验收用该章字符数）
- `CA`、`K` 与 `W` 的取值见 `references/翻译规范.md` 第六节；`K` 默认 0.7
- 用 `scripts/error_rate.py` 判定：退出码 **0** = 全通过；**1** = 符合国标但未达内部线；**2** = 不合格
- 内部线可调：改 `error_rate.py` 顶部常量，或传 `--rate-limit` / `--ii-density` / `--iii-density`
- **抽检范围**：万字以上抽检 10%~30%；万字以下全检
- **段落门禁失败先修再交**：`check_paragraph_map` 退出码非 0 时，把源文 + 译文交给修复者，只补/拆段落，不改已正确的句子；复查仍失败则停（S5），不得改名放行。**只准调空行与段界**：不得为过门禁增删句末标点、页码标记或改字；靠改标点变绿视为未修复
- **旧稿**：本流程不接手旧稿审校；旧稿不读、不比对、不作术语依据（见 `SKILL.md` G0）。若使用者明确要求审校旧稿，先把它当新任务重新定范围

**三层审校（全部为 [精确翻译]）**：

1. **双语审校**（对应 ISO 17100 的 revision）：每章默认抽 3 段对照 `source_en`（章节首尾段、含术语/数字/公式/专名的段落、清单一览）；表格/金额密集章加到 5–8 段；**补回过续页的章必须抽查续页段落**（实测：2-3 段查不出问题，5-8 段查出 5 条差错）。检查项对应差错类别：漏译/错译 → I 或 II 类；术语违规 → III 类；单位、符号、缩略语 → IV 类。**折扣换算与倍数表述必查**（两类高频 I 类，细则见 `references/数字与笔误陷阱.md`）。每处差错记入《审校差错清单》（**JSON 数组或 CSV**，`error_rate.py` 只读这两种）：字段 `class`/`chapter`/`location`/`source`/`target`/`note`；零差错时也建空清单（`[]`）留痕。
2. **一致性扫描**（自动）：同一英文术语 → 检出所有中文译法，非表内译法修正（记 III 类）；同一中文词对应多个英文源词时列出人工判断。
3. **流畅度筛查 + 定向审校**：先跑 `scripts/check_fluency.py`（0 token，排序器不是判定器），只把挑出的 top 5% 段落交一次审校（原文 + 译文对照），**不再逐章盲读 10%**。检查项：流畅性、段落衔接、无逐字硬译腔、无英文单位残渣（记 II 类）。成本从「读全书 10%」降到「读 top 5%」，约 1/12。

### A5. 知识沉淀（每本书翻译完成后必做）

1. **作者库回填**：新增术语、写作风格观察（口语程度、修辞、强调方式）逐条追加；纠正过的译法更新对应条目备注（不删历史，保留修正链）。**习语与句式**表（「英文习语 → 中文现成说法」）也要追加——这一层流畅度脚本抓不到，**只能靠审校发现后回写**，不回写下本书同一习语还会再错。
   - **🔁 回写已自动化**：`python scripts/draft_glossary.py --book-dir <书目录>` 从《审校差错清单》**自动起草条目草稿**到 `<术语体系>/_待确认.md`；**你只需删掉不同意的行、修正中间栏**，然后 `draft_glossary.py --promote --into <作者或类型 slug>` 一次回写。**为什么必须自动**：术语库的价值全在「越用越厚」，每本书都手动挑错记表的话没人会做——脚本管机械动作，「对不对」仍由使用者定
2. **类型库回填**：类型通用术语追加；「习语与句式」表同上（某条在 ≥3 本同类书出现后再从作者库移入类型库）；「语义不变量」栏按「本类型真正翻坏的维度」增删（每本书积累一条）
3. **重复词处理**：新译法修正旧译法则追加一行并注明（保留修正链）；本书专属译法只记入书级术语表，不污染类型库
4. **沉淀阈值**：某通用词在 ≥3 本书中出现后才同步进类型库
5. **🔴 术语库分两层：锚词 / 正文表达**：**锚词**短、可统一、进正文（判据「单看能懂、放进句子里不别扭」）；**正文表达**允许在语境里展开成释义（`Perceived Likelihood of Achievement` 锚词是「感知达成可能性」，正文可以写「**你觉得这事成的可能性有多大**」）。**规定译法不天然优于自然表达；用锚词的长度去套所有句子，正是翻译腔的来路。** 定期回看：`scripts/check_glossary_readability.py`（排序器，供人扫，不是门禁）
