# 关于流畅度质检（设计依据与操作）

> 2026-10-07 立。起因：A4 原来靠「AI 通读抽检 10% 章节」判流畅度，按比例烧 token 且无判定标准。
> 2026-10-07 整体优化时删去调研过程与实测数据的完整记录（原版在私有归档），本文只留**设计结论**与**怎么用**。

## 一、核心设计：排序器，不是判定器

翻译腔**没有权威阈值**——指标绝对值随语料、文体、作者变（「的」字密度「原创 4.7% vs 译文 5.97%」出自特定语料库，换书即失效）。所以：

- **不做「合格／不合格」判定器**，只做**全书内 z-score 排序器**；
- 输出「哪几段偏离全书最多」，把复核范围从「全书 10%」压到「top 5%」；
- 不设退出码门禁（恒为 0）——它的产出是**线索**，不是判决。

## 二、`check_fluency.py` 的 9 项指标

| 指标 | 计算 |
|---|---|
| 的字密度（/千字） | `的` 计数 / 汉字数 |
| 双重修饰（/百句） | 正则 `的[^，。；！？、]{1,12}的` |
| 代词+的（/千字） | 正则 `(我们\|你们\|他们\|我\|你\|他…)+的` |
| 平均句长（字） | 按 `。！？…` 切句取汉字均值 |
| 长句率 | 汉字数 > 40 的句占比 |
| 被字句（/千字） | `被` 计数 |
| 虚化动词（/千字） | 词表 `进行\|作出\|加以\|予以\|具有\|存在\|实现\|完成\|给予\|造成\|产生` |
| 配对连词（/千字） | 正则 `因为…所以`／`虽然…但是`／`如果…那么`／`当…的时候`／`对于…而言` |
| 介词框架（/千字） | 词表 `作为\|关于\|基于\|通过\|由于\|围绕\|针对` |

复合可疑度 `= Σ max(z, 0)`（九项方向已统一为「越高越像翻译腔」，只累计偏高那一侧）。

**噪声过滤（实测必需）**：① 公式／编号段（拉丁数字占比高、括号美元密集）按 `is_prose()` 剔除；② 极短章（样本小使 z 值虚高）由章级排名门槛 `--min-han-chap` 卡住（默认 400 汉字）。

> 另有两项**只报告、不进排序**：句长标准差（方向不明——AI 文本过匀偏低、人类偏高）、常用词覆盖率与超纲字率（需引入 5.6 万词表／一级字表，体积与依赖不划算，暂缓）。

## 三、怎么用（三段式，成本约盲读全书的 1/12）

```
check_fluency.py（0 token）→ top 5% 可疑段清单
  → 定向审校（AI 只读这些段，双语对照）
  → 差错记入《审校差错清单》，喂 error_rate.py 的 II 类
```

「定向审校者」prompt 见 `references/executor-prompt-templates.md` 第三节。

**实测校准**（同一本书「无 skill 版」与「skill 重译版」并成两池比较）：重译版在 9 项里 6 项更低（更低＝更少翻译腔），即**形式指标上重译版并不更「翻译腔」**。说明**指标只覆盖形式层，覆盖不到习语选择与语气**——用户的「不贴切」观感另有来源，两份信号要合起来看。

## 四、点缺陷：排序器抓不到的那一类

**`check_fluency.py` 的召回率实测为 0/5**：拿人工比读确认的 5 处生硬当正确答案，它们在排序里**全部落在后半区**（排名 238–476 / 537）。

根因：那 5 处是**点缺陷**（一个词选错、一个多余的字、一处英文残渣），而排序器量的是**段落分布**（的字密度、句长、连词密度）。一个 100 字的段落里错一个词，动不了它的 z 值。

**段落密度排序器结构性地看不见点缺陷，不能当主质检手段。** 点缺陷只能靠点检测器：

| 缺陷类型 | 检测器 |
|---|---|
| 习语直译（向下比烂） | `check_idiom.py`（查术语库习语表） |
| 英文单位残渣（`$1,000/wk`） | `check_unit_residue.py`（正则） |
| 生僻**字**（谘、迴） | `check_rare_chars.py`（字表） |
| 生僻**词**（被摄住） | `check_word_rarity.py`（词表）+ 一次 LLM 判定，**只出候选** |
| 单句语病／用词异常 | **不用 CGEC**（MacBERT4CSC：精度约 12%；整轮唯一真阳性在 `check_word_rarity` 候选里已有；依赖 600 MB 且会把共享环境的 `transformers` 升到 5.x，实测弄坏 `paddlex` 与 `qwen-asr`） |

> **教训（免得后人重犯）**：新工具要先问「这一格是不是已被现有链路覆盖」，再决定要不要装。
> 本格覆盖由 `check_word_rarity`（出候选）→ 一次 LLM 判定（做判断）这条链承担，不需另加 600 MB。

**词级为什么只能出候选**：「摄住」（不地道的生造搭配）与「举个」（jieba 把虚词与实词粘成的分词伪影）在**词典意义上不可区分**——都是「两个常用单字被粘成的未登录词」。任何基于词典/词表的手段都分不开，只能靠语义判断（LLM）。所以定位是**候选清单 → 一次廉价 LLM 判定**（约 265 条 ≈ 3k token），不进任何门禁。

## 五、习语表（`check_idiom.py` 的数据源）

**开源界没有「英文习语 → 规定中文译法」的数据集。** 已查证并排除：CC-CEDICT（方向反，中→英）、ECDICT（短语的常用度字段全空，筛不出习语）、PETCI／IdiomTranslate30（方向仍是中→外）、MIDAS（英中是分开的两份，不是对照表）、wordfreq（词表全是单词无短语，短语频率是从组成词外推的假值）、《牛津英语习语词典》（无开放电子版）。根本原因：**「规定译法」是规范性问题，只有人编词典才有权威答案，而那些全有版权。所以种子表只能自建。**

**一条习语怎么才算好**：把它按字面直译成中文，**中文读者看一眼就知道不对劲、而译者仍可能真的照字面写出来** → 进表并写上 `不写「X」`。

> 反例 `in a nutshell`：中文译者根本不会写成「在坚果壳里」，会自己写「简而言之」——这类条目**永远只产生误报**，不该进表。
> 一句话：**没有「字面直译很诱人」这个前提的条目，是白噪声。**

**两档输出，默认只开高置信那档**：

- `[错译]`——译文里出现了备注标明的**已知错译写法**（如「向下比烂的比赛」）。高置信，直接改。**默认只报这一档。**
- `[待查]`——源文命中了该习语、译文没出现规定说法。**判据本身有缺陷**：任何合法同义译法都会触发（实测「in a nutshell」被译成「一句话说」即误报）。**默认关闭**，要看得加 `--include-maybe`。

**全库统计（9 本书）**：46 条表项里只有 9 条曾被触发，37 条从未命中；真错译仅 2 处。`bottom line` 一条「待查」命中 45 次、真错译 0 次——**要么删，要么补上 `不写「X」` 后才能作为错译档生效**。死条目零成本（不触发即不耗资源），删了表更清爽。

## 六、习语内联：方向对，但不能无条件替换

**12 段对照实验**（两个独立译者，一个裸译、一个带习语约束）：无条件把 `bottom line → 净利润` 内联，译者把源文 6 处 `## Bottom Line:`（**小标题义**，意为「小结」）全译成「净利润：」，12 段里 6 段读不通——**比不内联更差**。

**而 `check_idiom` 对两版都报 0**（约束版确实用了规定说法）：**检查器只能验证「用没用规定说法」，验证不了「用得对不对」。**

**根因**：一条无条件的 `A → B` 替换规则，遇到「同一个词既是术语、又是标题/习语」的多义情形必然出错。

**复测（同日，约束改成带语境条件）**：6 处小标题**全部正确**译成「一句话总结：」，会计义处译「净利润」。**修复成立。**

**整章复测（2,360 词）**：裸译版把 `Bottom Line:` 译成「**底线**：」（正是被警告的典型翻译腔），约束版译「一句话总结：」——**裸译在短样本上偶然译对，放进整章就露出破绽；约束的价值要在长文本上才显出来。**

**三条结论**：

1. 「内联约束」的方向**是对的**，但**不能无条件替换**，必须写成「在什么语境下用哪个说法」；
2. **短样本会给出误导性结论**——要判断某个设计好不好，样本得有整章这个量级；
3. `check_idiom` 验证不了「用得对不对」，所以**批量套用规则前必须过样本确认闸门**（见 SKILL.md「改稿闸门」）。

## 七、方法出处（只留关键）

- Koppel & Ordan（ACL 2011）*Translationese and Its Dialects*——仅用功能词频率即可 96.7% 区分人工翻译与原创写作，翻译腔的信号强度远超直觉。
- PLOS ONE *Entropy-based discrimination between translated Chinese and original Chinese*——用 LCMC（原创汉语）与 ZCTC（翻译汉语）两个百万词平衡语料库，以熵指标区分，AUC 显著。
- 胡显耀《当代汉语翻译小说规范的语料库研究》——句长、的字频差的出处。
- **已排除的路**：中文可读性公式（衡量「对学习者多难」，不衡量「中文地道不地道」，两者可完全脱钩）、CGEC 语病工具（靶子是硬语病，而翻译腔的特征恰是语法完全正确）、COMETKiwi（en-zh 分数挤得很窄，绝对分不可信）、LanguageTool 中文（官方明说中文无拼写检查）、TextFlint（是鲁棒性评测工具，方向不对）。
- 同批可查的开源整书翻译项目（bilingual_book_maker、oomol-lab/epub-translator 等）**没有一个做译文流畅度质检**，其 QA 全落在「产物结构完整性 + 数字/术语机械一致性」；本管线的四件套（`check_numbers`／`check_structure`／`check_paragraph_map`／`error_rate`）在这一层已超过所有可查到的同类。
