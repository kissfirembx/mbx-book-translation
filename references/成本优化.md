# 成本优化（翻译管线）

> 起因：一天交付 4 本书（约 17 万中文字）成本偏高。
> 数字来自 DSH 本地账本的实测记账（不是推算）；查账用 `scripts/cost_report.py`，账本路径见 `references/环境与配置.md`。
> 2026-10-07 整体优化时删去过程性叙述，保留可执行结论与基线。

## 一、成本结构与基线（2026-09-15，交付 4 本书）

> ⚠️ 下表是「探索型译者」流程的实测值，**不是本管线的当前形态**（2026-10-07 重标定）。
> 本管线执行 P0 优化后（译者**零文件阅读、禁探索、写完即止**），实测每章只有 **3–4 次工具调用**、
> 单章 **28–58k token**；一本 32 章的书合计约 **1.2M**，而非下表推算的 50M+。
> 引用下表时请当作**上限**，不要当默认值。

| 指标 | 数值 |
|---|---|
| 模型调用 | **4,049 次**（约 40 次/章） |
| 缓存重发的输入 | **522.6M token**（每次调用平均重发 **129k** 上下文） |
| 未命中的输入 | **8.1M token**（每次调用平均新塞 2.0k） |
| 输出 | **3.30M token**（其中**推理 1.97M，占 60%**） |
| 费用 | **31.77 元**（约 1.87 元/万中文字，历史值） |

**成本结构：缓存重发 33% / 未命中输入 26% / 输出 42%。** 三个反直觉结论：

1. **钱不是花在译文上**：17 万中文字的译文本身只值 1–2 元。输出 token 有 3.3M，是因为其中六成是**推理 token**——模型在「想」，不是在「写」。
2. **计费不看窗口填充率**：子代理窗口只用 10% 和用满，单价一样。所以「让子代理吃更多章」不省钱——真正的因子是**调用次数 × 每次重发的上下文长度**。
3. **最大一桶是输出（42%），而输出的主体是推理**——能下压的是**调用次数**与**未命中输入**。

## 二、两根可下压的杠杆

| 杠杆 | 现状 | 手段 | 预期 |
|---|---|---|---|
| **调用次数** | 约 40 次/章 | 规范内联（译者零文件阅读）、禁探索、禁自检式通读、一行输出契约 | 降到 8–12 次/章，连带砍掉对应缓存重发 |
| **未命中输入** | 每次新塞 2.0k，日累计 8.1M | 大块原始数据不进编排层；核查合并为一次脚本调用；不重复读文件 | 砍 30–50% |

## 三、P0 已落地（零质量风险）

1. **规范冻结门**：批次 1 之前把格式与术语一次性冻死，之后除硬错误不再改规则。**收益最大**——消掉的是整类返工。
2. **规范内联 + 译者零文件阅读**：术语切片、格式清单、插图锚点直接拼进 prompt；译者只读源文一个文件。少 5 次工具往返 = 少 5 次上下文重发。
3. **译者禁止探索**：不得解包 EPUB、渲染 PDF、grep 全书、读其他章或旧稿——这些由预处理脚本一次性给出。
4. **禁止写完再通读自查**：核对交给脚本与 A4 审校。
5. **输出契约一行**：路径 + 字数 + 完成标记 + 异常项。
6. **编排层卫生**：目录与文件不进主会话，一律用脚本输出「计数 / 差异 / 异常行号」；多项核查合并成一次调用；已读过的文件不重复读。
7. **长行预折行**（`rewrap_source_lines.py`，零成本）：防 `read` 按行截断在 2000 字符导致静默丢尾。翻译前跑一次即可（细节见 `references/源文体检.md`）。

> **译者零文件阅读 ≠ 编排层免读源文**：P0-2／P0-3 约束的是**译者**，不是编排层。编排层必须自己通读源文一遍——成色判定（`preflight_probe.py`）、术语表、分节、指代锚点，全都出自这一次通读。把源文整包甩给译者、编排层只看文件名，等于把「这份源文该按什么规范处理」的判断也外包了，而判断错的代价是全批。

## 四、P1 / P2 已定

- **审校抽检 3 段**（原 5–8 段），仅表格/金额密集章加抽；审校仍只回 JSON。
- **同一本书连着跑完，不跨天**（缓存 TTL 小时到天级，跨天前缀按未命中重算）。
- **错峰跑批**：峰时单价约 ×2；用户已接受更长周期，正好吃满。
- **修复类操作走脚本**：术语替换、页脚清理、占位符统一等一次跑完，不交给代理逐章来回。
- **旧稿一律作废**：新书**直接首译**，不再比对旧稿、不再为「保留旧稿」付出任何阅读与核对成本（覆盖前仍按 G0 征求同意）。
- **审校覆盖比例**：默认每章 3 段；若某本连续两轮抽检零差错，下一本可降到 2 段（由主流程在《翻译任务规格.md》记录该决定）。

## 五、规则内联的边界：它只覆盖已知陷阱

把「已经踩过的坑」写成 prompt 内联规则，是**知识注入，不是能力提升**：它只对**已经见过的陷阱**有效。新书、新领域、新题型里没见过的数值/语义陷阱，规则一个字都拦不住，而且错得静默。

所以质量网必须是三层，缺一不可：① 译者 + 已知规则（`{FORMAT_BLOCK}` 内联折扣/倍数/术语等已知陷阱）；② 与陷阱无关的机械校验（`check_numbers.py`、`check_structure.py`，零 token）；③ 双语审校（唯一能兜住术语限定、语气、指代、讽刺这类语义问题的一层）。

任何「全靠规则」的方案，都是把质量押在「作者恰好见过这个坑」上。**新发现的坑必须回写规则**（`FORMAT_BLOCK` / `check_numbers.py`），否则每本书都要靠人重新发现一遍——规则库的价值在于累积。

## 六、目标与验证

- **目标**：单位成本从 **1.87 元/万中文字** 降到 **0.6–0.8 元/万中文字**（−60% 左右），靠「压调用次数 + 压未命中输入」合力，不牺牲译文；若某条措施没带来下降就回退。
- **验证方法**：动工前跑 `python scripts/cost_report.py --json` 存本次基线，收工再跑一次，把差值记进该书《翻译任务规格.md》；逐章记「调用次数 / 平均上下文 / 缓存命中 / 未命中 / 输出（含推理）」。**与本次开工前基线比，不拿 2026-09-15 的上限表当目标。**
- **取不到账本时**：如实写「取不到」，不跳过、不编造；此项不阻塞交付。
- **已知限制**：账本按天记账、不按书；跨书对比需按上面第 1 步自己记差值。

## 七、两个机械校验脚本的职责（零 token）

规则只能覆盖已知陷阱（第五节），所以另需一层**不看语义、只比结构**的机械校验。两个脚本都只读文件、不调模型：

- **`check_numbers.py`**：折扣方向（源文 `X% off` → 译文须有等值百分比或 `10 − X/10` 折；把 `80% off` 译成「八折」即 I 类）、数字对齐（源有译无即报缺失）、倍数方向（`Nx more` 译文出现「高 N 倍」即报）。
  - **它是召回优先的筛子，不是判官**：输出的「原文片段」为人工 3 秒定性准备；对已过人工审校的成品近乎零误报，OCR 来源的书噪声天然高。**它只覆盖数值类陷阱**——术语、语气、讽刺、结构、指代统统不在内，那批只能靠双语审校兜。
- **`check_structure.py`**：按语言无关的结构件点数，防整块漏译（整块漏译在数值上通常不可见）。
  - **门禁项**（源文 ≥3 处且译文覆盖 <70% 才报警）：占位符 `[PRODUCT]`→`[产品]`、舞台提示 `*Wait for response*`、`When to use`→`使用时机`。
  - **提示项**（只报数不动用退出码）：编号步骤、小节名计数——受排版约定影响大，当门禁会造成大面积误报。
  - **`--outline` 输出源文小节清单 → 译文标题，供逐条打钩。这一步不能省**：实测整块漏译时这类计数往往只差一处、**不触发阈值**，是按大纲逐条点数才看出来的。
- **落地位置**：A4 审校前必跑两个脚本（先清机械错，审校只处理语义）；两个脚本的输出并进审校 prompt 的附件；交付清单增加「数字校验 0 报错（或逐条已定性）」「结构件清点无报警（附大纲核对记录）」。
