# 已知坑（坑与处置）

> 主入口只保留影响执行的硬规则；本文件是完整清单，格式为**坑 → 处置**（过程叙述已删，2026-10-07 整体优化）。新坑照此追加。

## 一、源文提取与处理

| 坑 | 处置 |
|---|---|
| Python 在 Git Bash 下不识别 `/e/` 路径 | 用 `E:/` 或 `E:\` |
| 逐行移动注释/段落时行号会变 | 用「重建式」处理（标记跳过 + 目标后插入），不要逐行 insert/del |
| `content.find('标题')` 命中第一次出现（跨章同标题） | 处理章节内元素时先限定章节范围 |
| 全角/半角引号混用（`"` vs `“”`） | 核对时统一 |
| 目录条目页码无斜杠分隔 | 正则要兼容（`3.xxx144`） |
| **文字层 ≠ 文本可信**：PDF 可选中但内嵌字体 ToUnicode 可能错，换引擎读出来仍同错 | 定点混淆修正，不能靠换工具 |
| markitdown / PP-StructureV3 / 在线 PaddleOCR 对多栏、两端对齐、图密、坏字体映射的书表现差 | 勿当通用解，工具按能力需求选，别提前写死 |
| **图下小字注释**与**图中文字**（轴标签/图例）常混入正文 | 按位置区分（题注 vs 叙述式；图中文字剔除） |
| **图片引用有三种错误形态**：裸文件名、库根相对路径（含 `%20`）、前缀重复 | 统一为「按位置取前缀 + `<basename>`」（书根 `./figs/`、`zh/` 下 `../figs/`；成品内一律 `./figs/`）；历史成品需单独批量修（曾修过 5 本书共 418 处） |
| PDF「表格」常为图片数据图 | 用描边线检测判真伪，别把图当表拆 |
| **跨页断句**：一段话被分到多页，末尾无标点 | 需续接；别把页边界当段边界 |
| **目录页页码错位**（扫描书实测）：扫描件目录里标题与页码被 OCR 拆成不同行，译者按相邻配对 → **整串错位一格**（标题没号码、号码漂到下一行） | **用 bbox 按 y 聚行配对**（同一视觉行内的 title+number）重建目录；重建后**用「印刷页 + 偏移 = PDF 页」与实际章首页对账**，对得上才算修对 |
| **扫描件页眉被译成标题**（扫描书实测）：扫描书每页顶部的页眉（章名的全大写版）被 OCR 读成独立块，**译者会把它们当成标题译出来**，一章冒出 3–8 个重复标题 | 两侧都要做：① 源文侧 `clean_running_heads.py` 删「整块全大写 + 同文件 ≥2 次」的块（章标题是 Title Case，不会误删）；② **译者 prompt 里明写**「与章名重复的独立全大写短行是页眉，直接丢弃」。复核：每章 `#` 级标题应当只有 1 个 |
| **EPUB 图片提取坑**：图片可能嵌在 `<div>` 里而不在 `<p>` 里 | 必须扫描全部 `img` 标签（不限定父元素）并检查父元素——否则章节图全部静默丢失（实战：82 张图全部未提取） |
| **`[PDF 第 X 页]` 标记前后没有空行，会黏合两个段落**（某书实测某章 18 处／全书 375 处） | PDF 提取把页码标记单独放一行、且前后都不空行，于是「空行块」里常夹着两段正文。只并换行会把它们黏成一段（读感是「两段合成一段」）。**判据取自印刷事实**：跨页续接时页末行几乎排满、段落末尾才留白 → **标记前一行接近满行宽（≥ W−8）且无句末标点 ⇒ 跨页续接不断段；其余 ⇒ 段落边界，在此断段**。实测 375 处分为 续接 89 / 断段 286。处置：`unwrap_paragraphs.py --no-split`（标记并入段落行内，译者丢弃；零改写自检仍成立） |
| **小样文件不带批次标识、看不出场景**（使用者：分不清哪批小样、哪批给过反馈；文件还叫 `05_s2_engage` 看不出是什么场景） | 小样会因「换源文处理」「换规范」反复重做，`A_整章_05_engage.md` 这种命名看不出回次、反馈状态与内容场景。固定为中文命名：`_过程/小样/第N回小样_YYYY-MM-DD/`（内含 `_源文/`、`<序号>_<类型>_<章号>_<中文章名>.译.md`、`_本回说明.md`）与 `第N回反馈_YYYY-MM-DD/`（`反馈.md` + `修订版/`），另有 `_说明.md` 作结构与台账。**重抽开新回次，不覆盖旧回次**（见 `SKILL.md` 第 7 节 G2） |
| **EPUB 重复标题**：转换工具生成与 TOC 标题相同的书眉标题 | 提取时跳过与章节标题重复的 h1；正文中的重复列表是提取产物，完整保留不删（译者禁止自行删重复，统一在 A3 用 `clean_flat_lists.py` 清理） |
| **嵌套清单被压平**：EPUB 的嵌套 `<ol>` 常被展平成三遍同内容 | 按源 txt 的扁平顺序逐条完整译出，**不按 EPUB 重排、不删重复**（2026-09 某书实测：单章 8 个父项、5 个带嵌套子清单，展平后 24 条） |
| **EPUB spine 续页被丢**：一章拆成多个 spine 文档，**续页没有自己的章标题** | 按标题切分的脚本会整段丢掉这类续页。实战：某书 31 章丢 5 个续页，其中一章 905 词条只覆盖 2.4%；译本交付前看起来「完整、有完成标记、图片数对得上」，只有 `check_epub_coverage.py` 能发现 |
| **`chapter-figs.json` 从旧译稿反推** | 旧译稿可能就缺章（含缺图），反推会把缺口继承下来——**必须从 EPUB 生成** |

## 二、段落与 Obsidian 标记

| 坑 | 处置 |
|---|---|
| **把口语源当书稿处理**（代价：整本返工） | 讲座/访谈/播客的字幕靠口头语、问答来回、自我更正承载意思；按书籍规范（并段、删填充词、书面化）处理会把论证台阶压平——`error_rate` 0‰、四个脚本全绿，用户却读不懂。先跑成色体检拿档位，口语源另用语体清单（见规范冻结与 `executor-prompt-templates.md` 第四节） |
| **「一段对一段」没有门禁**（代价：整本返工） | 并段**不违反字符级零改写校验**（并段只改空白），`check_numbers`／`check_structure`／`qa_report` 都不看段落边界。处置：`check_paragraph_map.py` 做门禁，凡动换行的脚本落盘前必跑 |
| **体检绑在格式上** | 跳过的理由应是「这一步不需要」，不是「格式不对口」——体检按「要不要开译」触发，不按扩展名触发 |
| **Anna's Archive 的 MD 把页眉升格成 `#` 标题** | 转换产物里每个页眉都成了 `#` 级标题（某书 53 个 `#` 里 36 个是页眉，`# SOME BOOK TITLE` 一个就 20 次）。**不先清就按 `#` 切分，会切出几十个假章节。** 判别：**真标题是 Title Case，页眉是全大写**。处置：**`clean_running_heads.py` → `split_md_chapters.py`，顺序不能反**；判据是「全大写 且（同文件重复 ≥2 次 或 与某个 Title Case `#` 标题同名）」 |
| **清理脚本用「归一化键」匹配 → 连带删掉同名真标题**（2026-10-07 实测） | `clean_running_heads.py` 原先把待删块存成**归一化键**集合，而归一化会抹掉大小写——于是 `# START HERE`（页眉）和 `# Start Here`（真标题）同键，删页眉时把真标题一起删了，**整章正文被并进上一章**（表现：某「章」正文块数暴涨到 2793 词）。处置：待删集合改存**原始块文本**，按文本精确匹配；同名判据另外要求「本行必须全大写」 |
| **段落门禁对「边界是机器重建的」源文只能是参考项**（某书实测 21/22 标红） | 三类原因都不是译者的错：① 源文标题标记在提取时丢了，译者还原成 `##`/`###` 是对的，但门禁排除了 `#` 块；② 源文有段落中间的空白行（PDF 提取产物）；③ 两边段落切法本就不同。`check_paragraph_map.py` 已改为**两边同一把尺子**并新增 `--tolerance`。**政策**：源文 **Ⅰ 档 → tolerance 必须为 0，硬门禁**；**Ⅱ/Ⅲ 档 → 用百分比容差并在书 README 记录偏差**；同时**必须用「英文词 → 中文字」比值核查内容完整性**。**段数对不上 ≠ 内容丢，别用回切去消灭差异。** |
| **空行块已经是段落，却被短行启发式切碎**（代价：整本「一句一段」，返工重译；某书实测 143→163） | 源文的空行分段本来就是书的段落边界时（PDF 提取保留了段间距、`preflight_probe` 判「段落已成形」），**不能用「短行＝段末」去切**——段中偶尔的短行会被误当段末。处置：`unwrap_paragraphs.py **--no-split**`（只并块内换行），落盘后**段数必须等于源文空行块数**。症状：一句话的举例、行动步骤的每一步各占一段（）。⚠️ **并段只改空白，字符级零改写校验照样通过**，所以只能在**改之前**判对 |
| **星号（`*`）是 Obsidian 的雷** | 源文 `*` 兼作列表符（`* Option #1:`）与斜体强调（`*aspect*`）。译文留下单个 `*`，Obsidian 会当斜体或标签，渲染成乱码。**铁律：译文里只允许成对的 `**`，正文不得有落单的 `*`**（源文斜体按作者档案改成加粗、行首 `* ` 转 `- `）。**⚠️ 例外**：独立成行的 `***`／`* * *` 是作者有意的装饰分隔符，**转成 `---`** |
| **井号（`#`）是另一颗雷，更隐蔽** | 源文 `Option #1` 直译成 `选项 #1：…` 后，`#1：中文` 会**整条被 Obsidian 索引成标签**。机理：标签 = `#` 紧跟非空白字符，纯数字不算、但后面接了中文或全角标点就算。**规定写法：转义成 `\#1`**（阅读视图显示可见的 `#1`，语义零改动）；`#` 后不接数字的（`#tag` 式）同样转义。`check_markup.py` 已加检测（第 ⑦ 类）；转换走 `patch_preview.py` 闸门，正则须**先挖掉行首的 `#{1,6}` 标题标记** |
| **改完要拿 Obsidian 自己复核，别只看脚本** | `obsidian eval` 查单文件 `getFileCache(f).tags` 最权威（返回 `[]` 才算真清干净）；`obsidian tags` 看全库索引条目数变化。**脚本绿 ≠ Obsidian 不索引。** |
| **MD 转换产物（Anna's Archive）的段落门禁偏差是常态**（实测 15 处） | 源文约 **31% 的空行块末行没有句末标点**（转换时丢的）。译者补上标点后，门禁的「短且无句末标点＝标签，排除」这条在两侧表现不同 → 每章 ±1~+3 段。**判据：偏差方向不一致（有 ＋ 有 −）就是边界抖动，不是并段/拆段**——系统性并段只会单向为负、拆段只会单向为正。抽查 3 处逐句核对，译文完整。**政策：Ⅰ 档仍按 tolerance 0 硬门禁跑；系统性单向并段 → 回切源文边界；混合方向、±1~3 的边界抖动 → 记入 README 并抽查，不回切** |
| **图片占位两侧形态不同 → 段落门禁误报**（同批实测，单文件差 6 段） | 源文写 `[The image shows …]`（半角方括号，行末 `]` **恰好在句末标点集合里**）→ 被判成正文段；译文写全角 `［插图：…］`（行末无句末标点）→ 被排除。已修：`META_BLOCK` 增加「整行半角方括号包裹、内容 ≥12 字符」一条 |
| **逐页页脚会与正文挤在同一空行块里，形态判据抓不到** | 源文 `6    Copyright 2025 by BUMBLE IP, LLC NOT FOR DISTRIBUTION` 与前后行无空行 → 整块非全大写 → `clean_running_heads.py` 不删。**处置：源文清理时加 `--footers`**；译文侧按 `references/data/footers.json` 的同一模式删，并**连带删其后紧跟的那个 `---`**（否则剩两条相邻水平线） |
| **`check_paragraph_map.py` 原先只认 `.txt` 源文**（2026-10-07 修） | 对 `.md` 源文（如某系列）直接报「没找到可配对的源文/译文」，**段落门禁形同不存在**。已改成 `.txt`/`.md` 都扫（同名时 `.txt` 优先） |

| **MD 源清理页眉要加 `--ext .md`** | `clean_running_heads.py` 默认只扫 `.txt`；对 Anna's Archive 的 `.md` 源直接跑会 0 命中，必须显式 `--ext .md` |

| **`---` 默认是作者分段符** | 默认保留为 `---`；只有与 `[PDF 第 X 页]`/页脚页码明确对齐、且前后句被截断时，才按分页断点删除并接回。不要仅凭「像被截断」就删。判据记入《翻译任务规格.md》 |

## 三、改稿与闸门

| 坑 | 处置 |
|---|---|
| **转义类替换的正则必须排除「已转义的」** | 把 `#` 转成 `\#` 若用 `#(?=\d)`，**再跑一次会把 `\#1` 变成 `\\#1`**。正确写法 `(?<!\\)#(?=\d)`。闸门的幂等自检就是为这一类加的——**看到 `⚠ 非幂等` 先怀疑二次转义** |
| **闸门的「计数」与「落盘」必须是同一机制**（实测：报 6 处、0 处生效，而 `--expect` 照样通过） | 计数按**行**、落盘却对**整篇文本**做一次 `sub` 时，带 `^`/`$` 的模式在整篇上（无 `re.MULTILINE`）只匹配首尾——于是「行行都报命中、实际一处没改」。**落盘必须逐行**，与计数、与样本展示三者一致 |
| **`merge-config.json` 会与轮次重命名脱节**（实测 4 本书的 `suffix` 还写着 `_重译版`、指向不存在的文件） | 轮次归档改了文件名、配置没跟着改，合并直接报「未找到章节文件」。**合并前先 `--dry-run` 干跑**；`suffix` 要与 `zh/` 实际后缀一致、`out_name` 要与顶层成品实际名一致 |
| **`escape_hash.py` 不能对术语库或含代码的文件跑** | 它按**行**变换、**看不见代码块状态**，会把 `` `#` ``、`| Format #4 … |` 这类**代码与英文原名**一并转义（2026-10-07 实测：对 `_术语体系/alex-hormozi.md` dry-run，5 处里 4 处是误伤，还报了非幂等）。**术语库的 `#` 只手工改**；译文目录可以放心跑（正文里没有裸 `#`） |
| **「历史成品带标签」先分清是内容还是缺陷** | 同一批扫描里，`#gymlord`／`#Pepsi` 是**原书的社媒话题标签**（出现在 `source_en/`，属内容，**不该转义**）；`#1：…`／`#mozination` 在**译文正文**里才是缺陷。**判据：看它在 `source_en/` 还是 `zh/`**。归档轮次（`_归档/`）是历史快照，一般不动 |

## 四、内联与规则生效

| 坑 | 处置 |
|---|---|
| **作者档案的「写作风格 / 强调方式」不内联 = 等于没写** | 档案里写着「斜体表示强调——译文用加粗对应」，但译者只读源文、看不到档案，于是照抄了 `*斜体*`。**凡影响逐句落笔的条目（强调方式、口语程度、称谓、单位习惯），必须与术语、习语一起内联进译者 prompt**，否则规则躺在库里不生效 |

## 五、质检脚本的已知误报

- **② 换行/断句**：**诗行结构**（诗歌、拉丁引文逐行排列）、引用署名行、列表式标题会被报为断句候选——古典/诗歌类书籍抽样确认后忽略即可，脚本不为此收窄（收窄会漏报真断句）。
- **① 识别错误**：**字母＋数字的型号/编号标签**（`1A`、`FNB`、`302`）会被判成「数字夹字母」——某讲座成品报 6 处，逐条核对后**全是假阳性**。噪声比真信号多时，报告等于没报；看到这一类先按标签形态剔除再判真伪。
- **③ 舞台提示（源文 `*斜体*`）在英译中下天然不对称**（某系列 11 本实测，7 章误报）：源文按「`*` 之间 3–45 字符」计数（英文词 `and` = 3 字符），译文沿用同一口径就会漏掉 `**并**`（1 个汉字 < 3）→ 整章误报「漏译」。抽查原文后译文完好。**译文侧下限已改为 1**。
- **④「结构件缺失」报警先看是不是短强调词**：同一批里 `Closing 04` 仍报「31 → 19」，逐条核对是**一致风格选择**——源文 `*"客户原话"*`（斜体引语）译成「客户原话」（中文引号已承担区分功能，未再加粗）。**语义完整，不是漏译。** 判据：门禁只报「数量不对等」，**对等与否要回原文看**。
- **⑤ 四处质检脚本曾硬编码只认 `.txt` 源文**（2026-10-07 修）：`check_paragraph_map`／`check_structure`／`check_idiom`／`check_numbers`（后者连 `--book-dir` 都没有）。对 `.md` 源文（如《某商业书》系列）直接报「共 0 章」「文件 0 个」——**门禁静默失效，比误报更危险**（报告是绿的，其实一条没查）。四个已全部支持 `.txt` + `.md`。
